# Codex와 Claude Code 역할분담 백로그

## 공통 작업 규칙

- `docs/00-프로젝트-컨텍스트.md`의 상태값과 권한 정의를 단일 기준으로 사용한다.
- API, DB 스키마, 화면 변경은 관련 명세를 함께 갱신한다.
- 외부망과 내부 행정망 사이의 직접 DB 연결을 구현하지 않는다.
- 각 기능은 단위 테스트와 권한 테스트를 통과한 뒤 병합한다.

## Codex 담당

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| C1 | 도메인 모델과 DB 스키마 | 신고, 품목분류·규격·수수료 마스터, 사진, 상태이력, 권한, 수거구역 테이블 정의 |
| C2 | 업무 API와 상태 전이 | 허용되지 않은 상태 변경을 차단하고 이력을 기록 |
| C3 | 위치·수수료·결제·배정 로직 | 주소·좌표 검증, 품목 수수료 계산, 계좌이체 입금대기·입금확인 상태 관리, 입금 확인 후 구역 배정 |

| C4 | 내부망 연계 인터페이스 | 재처리 가능한 접수 동기화와 오류함 구현 |
| C5 | 최종 담당자 데이터 검증 API | 정합성·연계·결제·미처리 현황을 읽기 전용으로 제공 |
| C6 | 권한·감사·보안 테스트 | 역할별 접근 차단과 주요 열람·다운로드 로그 검증 |

## Claude Code 담당

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| A1 | 시민 신고·결제 모바일 화면 | 분류·검색 기반 품목·규격 선택, 위치, 사진, 배출일, 계좌이체 납부 안내, 접수 조회 흐름 완성 |
| A2 | 내부 담당자 대시보드 | 지도·목록·상세 화면에서 검토와 배정 가능 |
| A3 | 수거 담당자 모바일 업무 화면 | 오늘의 작업, 신고지점·현재 위치 지도 확인, 길찾기 연결, 완료·미수거·사진·현장변경 요청 처리 가능 |
| A4 | 최종 담당자 데이터 검증 화면 | 오류 목록, 집계, 승인 상태를 읽기 전용으로 표시 |
| A5 | 접근성·반응형·현장 UX 검증 | 모바일과 내부 PC 환경에서 핵심 흐름 점검 |

## 인수인계 계약

Codex는 API 명세와 테스트용 데이터 세트를 제공한다. Claude Code는 각 화면에서 필요한 요청·응답과 오류 표시 규칙을 확정한다. 화면 요구사항으로 API 변경이 필요하면 먼저 명세를 수정하고, 호환성 영향 여부를 기록한다.

## 첫 번째 구현 단위

1. Codex가 신고·품목·결제·상태이력·수거구역의 스키마와 API 계약을 확정한다.
2. Claude Code가 시민 신고·결제 화면과 내부 접수 목록 화면을 구현한다.
3. Codex가 현장 위치 확인, 완료·미수거·현장변경 요청 API와 내부 연계를 구현한다.
4. Claude Code가 수거 담당자 모바일 업무 화면, 지도 기반 배정 화면, 최종 담당자 검증 화면을 구현한다.
5. 양쪽이 역할·망 구간·위치권한·상태 전이 테스트를 공동 검증한다.
